# آزمون بار

`quiz-load.js` سنگین‌ترین سناریوی سامانه را می‌سنجد: ۱۵۰ دانشجوی
هم‌زمان در آزمون (NFR-07، وظیفهٔ M4-16).

## پیش‌نیاز

۱. [k6](https://k6.io/docs/get-started/installation/) نصب باشد.
۲. سرور بالا باشد و یک آزمون **منتشرشده** با چند سؤال وجود داشته باشد.
۳. محیط، `ENVIRONMENT=development` باشد تا کد ورود ثابت `۱۱۱۱۱۱` کار کند.

## اجرا

```bash
k6 run -e BASE_URL=http://localhost:8000 -e QUIZ_ID=<uuid> infra/k6/quiz-load.js
```

## آستانه‌ها

| سنجه | حد |
|------|-----|
| `answer_save_duration` p95 | زیر ۴۰۰ms |
| نرخ خطای ذخیرهٔ پاسخ | زیر ۱٪ |
| نرخ خطای شروع تلاش | زیر ۱٪ |

عبور از آستانه یعنی k6 با کد خروج غیرصفر تمام می‌شود.

## نکته

هر VU با شمارهٔ موبایل خودش وارد می‌شود. اگر همه با یک حساب وارد
می‌شدند، قید «یک تلاش فعال در هر لحظه» بقیه را رد می‌کرد و تست به‌جای
بار واقعی، ۱۴۹ خطای ۴۰۹ می‌سنجید.

محدودیت نرخ OTP (`OTP_PER_IP_PER_HOUR`) در اجرای محلی زود پر می‌شود —
پیش از هر اجرا `redis-cli FLUSHDB` بزنید یا سقف را موقتاً بالا ببرید.
