# ۰۳ — معماری اطلاعات و نقشهٔ صفحات

مرجع پیاده‌سازی مسیرها در Next.js App Router. هر مسیر شامل: نقش مجاز، هدف،
نوع رندر، و اجزای کلیدی.

**انواع رندر:** `SSG` ایستا · `SSR` سمت سرور · `RSC` کامپوننت سرور با داده پویا ·
`CSR` سمت کلاینت (تعاملی)

## ۳.۲ ناحیهٔ عمومی — `(marketing)`

| مسیر | رندر | هدف | اجزای کلیدی |
|------|------|-----|--------------|
| `/` | SSG + ISR ۱h | تبدیل بازدیدکننده به کاربر | Hero با پیام «از مصرف‌کننده به تولیدکننده»، ۴ مسیر رشد، آمار زندهٔ سامانه، ۳ داستان موفقیت، فراخوان ثبت‌نام |
| `/about` | SSG | فلسفه و تیم | متن چشم‌انداز، نقشهٔ راه عمومی |
| `/courses` | ISR ۱h | ویترین دروس | کارت‌های درس، فیلتر مقطع، «ثبت‌نام» |
| `/courses/[slug]` | ISR | معرفی یک درس | سرفصل هفته‌ها (بدون محتوا)، استاد، آمار |
| `/projects` | ISR ۱۵m | ویترین پروژه‌ها | کارت‌ها، فیلتر نوع/مهارت، تشویق به ورود برای دیدن تطابق |
| `/projects/[id]` | ISR | معرفی یک پروژه | شرح، مهارت‌های لازم، تیم، «درخواست پیوستن» |
| `/ideas` | ISR ۱۵m | بانک ایده | فهرست، رأی (نیازمند ورود)، فیلتر |
| `/u/[username]` | SSR (کش ۱ دقیقه) | نیمرخ عمومی | مهارت‌ها، پروژه‌ها، گواهی‌ها، پژوهش، نشان‌ها — بخش خاموش از سرور نمی‌آید |
| `/verify/[code]` | SSR | راستی‌آزمایی گواهی | معتبر، **باطل‌شده با دلیل**، یا ۴۰۴ برای کدی که صادر نشده (ADR-0017) |

**پیاده‌سازی M7 بخش د:** صفحهٔ اصلی رندر سرور با ISR یک‌ساعته از `/public/stats` و `/public/stories`؛ `/courses` و `/about` عمومی ساخته نشدند. مهمان در `/projects`، `/ideas`، `/research` و `/city` به ورود فرستاده نمی‌شود (ADR-0017).

**قاعدهٔ صفحهٔ اصلی:** در یک نگاه (بدون اسکرول) باید مشخص باشد این سامانه چیست
و کاربر چه سودی می‌برد. بدون واژه‌های تهی مثل «راهکار جامع».

## ۳.۳ ناحیهٔ ورود — `(auth)`

| مسیر | رندر | جریان |
|------|------|-------|
| `/login` | CSR | ورودی موبایل → ارسال OTP. تب دوم: ورود با رمز. |
| `/verify` | CSR | ۶ خانهٔ کد با چسباندن خودکار، شمارنده معکوس، «ارسال مجدد» |
| `/onboarding/basic` | CSR | نام، نام خانوادگی، اطلاعات دانشگاهی |
| `/onboarding/courses` | CSR | انتخاب دروس نیم‌سال جاری |
| `/onboarding/survey/[step]` | CSR | ۴ گام ارزیابی نیمرخ (§FR-PROF-01) |
| `/onboarding/results` | CSR | **لحظهٔ طلایی:** نمایش اولین پیشنهادهای پروژه |

**الزامات تجربهٔ کاربری این ناحیه:**
- هیچ صفحه‌ای بیش از ۷ فیلد ورودی نداشته باشد.
- نوار پیشرفت در همهٔ گام‌ها.
- دکمهٔ «بعداً» در همهٔ گام‌های غیر الزامی.
- ذخیرهٔ خودکار پس از هر تغییر (debounce ۸۰۰ms).
- کیبورد موبایل: نوع `tel` برای شماره، `numeric` برای OTP.

| `/teach/quizzes` | فهرست آزمون‌ها |
| `/teach/quizzes/[id]/edit` | ویرایشگر آزمون |
| `/teach/quizzes/[id]/grade` | **صف تصحیح تشریحی** — یک سؤال در هر صفحه برای همهٔ دانشجویان |
| `/teach/quizzes/[id]/analytics` | تحلیل آزمون: توزیع نمره، پایایی، ضریب دشواری و تمیز، همبستگی با بقیه، توزیع گزینه |
| `/teach/question-bank` | بانک سؤال |
| `/teach/projects` | پروژه‌های تحت نظارت با شاخص سلامت |
| `/teach/review-queue` | **صف واحد بررسی:** همهٔ تحویل‌دادنی‌های منتظر |

**ساخته‌شده (ADR-0019 و ADR-0022):** همهٔ مسیرهای بالا، به‌علاوهٔ
`/teach/offerings/[id]/weeks/[n]` (ویرایشگر هفته؛
به‌جای `…/weeks/[n]/edit`)، `/teach/offerings/[id]/quizzes` و
`/teach/offerings/[id]/settings`، و ویرایشگر آزمون در `/teach/quizzes/[id]/edit`
با زبانه‌های `/grade` و `/analytics`. پوسته مثل پنل مدیریت است؛ زبانه‌ای که
بیننده مجوزش را ندارد (دستیار: دفتر نمره و تنظیمات) نشان داده نمی‌شود. پیوند
«تدریس» در هدر برای استاد، دستیار و مدیر آموزشی همان «جابه‌جاگر نقش» §3.7 است.

**صف تصحیح تشریحی — مشخصهٔ ویژه:** تصحیح **بر اساس سؤال** انجام می‌شود، نه بر اساس
دانشجو. استاد یک سؤال را برای همهٔ دانشجویان پشت سر هم می‌بیند. این کار سرعت و
یکنواختی نمره‌دهی را به‌شدت بالا می‌برد و در LMSهای رایج وجود ندارد.

**تحلیل سؤال — مشخصهٔ ویژه:** نمایش ضریب دشواری (نسبت پاسخ صحیح) و ضریب تمیز
(همبستگی نقطه‌ای دو رشته‌ای) تا استاد بفهمد کدام سؤال بد طراحی شده است.

## ۳.۷ ناوبری

### ناوبری اصلی (سایدبار دسکتاپ / نوار پایین موبایل)

**دانشجو:**
```
داشبورد · دروس · پروژه‌ها · پژوهش · کسب‌وکار · ایده‌ها · تیم
```
موبایل فقط ۵ مورد اول را در نوار پایین نشان می‌دهد؛ بقیه در منوی «بیشتر».

**استاد:** کلیدواژهٔ تفکیک، جابه‌جاگر نقش (Role Switcher) در هدر است —
استاد می‌تواند بین نمای «دانشجو» و «تدریس» جابه‌جا شود.

### هدر (در همهٔ صفحات اپلیکیشن)
```
[لوگو]  [جستجوی سراسری ⌘K]        [امتیاز و سطح] [زنگوله] [آواتار ▾]
```

### جستجوی سراسری (⌘K / Ctrl+K)
جستجوی یکپارچه در: دروس، پروژه‌ها، ایده‌ها، افراد، منابع، و **دستورات**
(«ثبت ایده»، «رفتن به داشبورد»). این یک ویژگی کوچک با اثر بزرگ بر سرعت کار است.

پیاده‌سازی (M7 بخش د): `GET /search` با هفت گروه (درس، پروژه، ایده، کسب‌وکار، موضوع پژوهشی، فرد، منبع)، هر گروه با قاعدهٔ دیده‌شدن فهرست خودش؛ دستورات فهرست ثابت کلاینت و وابسته به نقش؛ الگوی combobox/listbox با `aria-activedescendant` ([ADR-0017](../adr/0017-public-certificates-admin-and-search.md)).

### مسیر راهنما (Breadcrumb)
در همهٔ صفحات تودرتو، با جهت راست‌به‌چپ:
`دروس ‹ مهندسی ترابری ‹ هفتهٔ ۵ ‹ آزمون`

## ۳.۸ حالت‌های صفحه (State Matrix)

**هر صفحه باید هر چهار حالت را پیاده‌سازی کند. این بند قابل مذاکره نیست.**

| حالت | الزام |
|------|-------|
| **بارگذاری** | اسکلت (Skeleton) هم‌شکل محتوای نهایی، نه چرخندهٔ وسط صفحه |
| **خالی** | تصویرسازی + توضیح + **دکمهٔ اقدام مشخص**. مثال: «هنوز پروژه‌ای نداری — ۳ پروژه برایت پیدا کردیم» |
| **خطا** | پیام قابل فهم فارسی + دکمهٔ «تلاش دوباره» + کد خطا برای پشتیبانی. هرگز نمایش Stack Trace. |
| **موفق با داده** | محتوای اصلی |

**حالت‌های خاص اضافی:**
- **بدون دسترسی:** توضیح اینکه چرا و چگونه دسترسی بگیرد، نه صرفاً «۴۰۳».
- **آفلاین:** بنر دائمی بالای صفحه + غیرفعال کردن اقدامات نیازمند شبکه.

| `md` | ۶۴۰–۱۰۲۴ | دو ستونی، سایدبار جمع‌شونده |
| `lg` | ۱۰۲۴–۱۴۴۰ | سایدبار ثابت، محتوای سه‌ستونی |
| `xl` | > ۱۴۴۰ | حداکثر عرض محتوا ۱۲۸۰px، حاشیهٔ متقارن |

**قاعدهٔ جدول در موبایل:** هیچ جدولی در موبایل اسکرول افقی نمی‌گیرد. جدول‌ها به
فهرست کارت تبدیل می‌شوند که هر کارت، ستون‌ها را به‌صورت برچسب/مقدار نشان می‌دهد.
