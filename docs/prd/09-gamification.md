# ۰۹ — امتیازدهی و گیمیفیکیشن

**فلسفه:** امتیاز باید **ارزش واقعی خلق‌شده** را بازتاب دهد، نه میزان زمان
صرف‌شده در سامانه. هر امتیازی که بدون خلق ارزش قابل کسب باشد، یک باگ است.

---

## ۹.۱ چهار دستهٔ امتیاز

| دسته | چه چیزی را می‌سنجد | نمونه فعالیت |
|------|---------------------|--------------|
| `LEARNING` | تسلط بر دانش | آزمون، مطالعه، حضور، تحویل درسی |

دانشجوی پژوهش‌محور نباید با یک کارآفرین در یک جدول رقابت کند.

## ۹.۴ سطوح

سطح از **مجموع امتیاز همهٔ دسته‌ها در طول عمر حساب** محاسبه می‌شود.

```
آستانهٔ سطح n  =  round(50 × (n − 1)^1.6)      n ≥ 1
```

| سطح | آستانه | عنوان |
|-----|--------|-------|
| ۱ | ۰ | تازه‌وارد |
| ۲ | ۵۰ | کاوشگر |
| ۳ | ۱۵۲ | یادگیرنده |
| ۴ | ۲۹۰ | سازنده |
| ۵ | ۴۵۹ | همکار |
| ۶ | ۶۵۷ | مشارکت‌کننده |
| ۷ | ۸۷۹ | ماهر |
| ۸ | ۱۱۲۵ | خبره |
| ۹ | ۱۳۹۳ | پیشرو |
| ۱۰ | ۱۶۸۲ | معمار |
| ۱۲ | ۲۳۱۸ | استاد کار |
| ۱۵ | ۳۴۱۰ | مرجع |
| ۲۰ | ۵۵۵۹ | افسانه |

> جدول بالا مرجع تست است: `test_level_thresholds_match_table()` باید دقیقاً
> همین اعداد را از فرمول تولید کند. اگر فرمول تغییر کرد، جدول هم باید تغییر کند.
>
> **اصلاح شد — [ADR-0012](../adr/0012-ledger-revisions-and-gamification-gaps.md).** نسخهٔ پیش‌نویس جدول از سطح ۷ به بعد با فرمول
> نمی‌خواند (۸۸۰ به‌جای `50 × 6^1.6 = 879.2 → 879`). فرمول تعریف است؛
> جدول اصلاح شد.

رشد نمایی با توان ۱.۶ انتخاب شده تا سطوح اولیه سریع و دلگرم‌کننده باشند و
سطوح بالا معنادار بمانند.

**نمایش:** همیشه «۱۳۰ امتیاز تا سطح بعد» نشان داده شود، نه فقط عدد خام.

## ۹.۶ نمرهٔ یادگیری (Learning Score)

عددی ۰ تا ۱۰۰ برای هر دانشجو در هر **ارائهٔ درس**. متفاوت از امتیاز گیمیفیکیشن:
این یکی **نسبی و درسی** است، آن یکی مطلق و کلی.

```
LS = 100 × ( 0.40 × Q + 0.25 × S + 0.20 × P + 0.15 × A )
```

| نماد | مؤلفه | محاسبه |
|------|-------|--------|
| `Q` | آزمون | میانگین وزنی `(score / total)` همهٔ آزمون‌های منتشرشده |
| `S` | مطالعه | `منابع الزامی تکمیل‌شده / کل منابع الزامی منتشرشده` |
| `P` | پروژه | `مراحل تأییدشده / کل مراحل الزامی` پروژه‌های متصل به این ارائه |
| `A` | حضور | `(PRESENT + 0.5×LATE + EXCUSED) / کل جلسات` |

**قواعد:**
- **مخرج فقط شامل محتوای منتشرشده است.** دانشجوی هفتهٔ سوم نباید به‌خاطر
  هفته‌های منتشرنشده نمرهٔ پایین بگیرد.
- اگر یک مؤلفه در ارائه وجود نداشته باشد (مثلاً بدون حضور و غیاب)، وزنش صفر و
  بقیه بازنرمال می‌شوند.
- وزن‌ها در `course_offerings.grading_policy` قابل تغییر برای هر ارائه‌اند.
- محاسبه **بی‌درنگ** است (در لحظهٔ درخواست از نماهای تجمیعی)، نه ذخیره‌شده.

### رابطه با نمرهٔ نهایی

این دو **یکی نیستند** و نباید خلط شوند:

| | Learning Score | نمرهٔ نهایی (`enrollments.final_grade`) |
|---|---|---|
| بازه | ۰ تا ۱۰۰ | ۰ تا ۲۰ |
| محاسبه | خودکار و پیوسته | **دستی توسط استاد** |
| ماهیت | شاخص پیشرفت، ابزار پایش | نمرهٔ رسمی دانشگاهی |
| قابل اعتراض | خیر | بله |

**Learning Score یک پیشنهاد است، نه یک الزام.** در صفحهٔ دفتر نمره، کنار هر
دانشجو نمایش داده می‌شود و دکمهٔ «اعمال به‌عنوان نمرهٔ پیشنهادی» (`LS × 0.2`)
وجود دارد — اما استاد همیشه عدد نهایی را خودش تأیید می‌کند.

> **چرا خودکار نیست؟** مسئولیت نمره‌دهی با استاد است و عواملی (کیفیت کار،
> پیشرفت فردی، شرایط خاص) در هیچ فرمولی نمی‌گنجند. سامانه‌ای که نمره را
> خودکار ثبت کند، اعتماد استاد را از دست می‌دهد.

## ۹.۷ جدول رتبه‌بندی

### دامنه‌ها

| دامنه | توضیح |
|-------|-------|
| `GLOBAL` | کل سامانه، نیم‌سال جاری |
| `OFFERING` | یک ارائهٔ درس |
| `UNIVERSITY` | یک دانشگاه |
| `CATEGORY` | یک دستهٔ امتیاز |

### قواعد انصاف

۱. **همیشه محدود به نیم‌سال.** رتبه‌بندی مادام‌العمر، تازه‌وارد را ناامید می‌کند.
۲. **فقط ۱۰ نفر برتر نمایش داده می‌شوند** + رتبهٔ خود کاربر + صدک او.
۳. **هیچ‌کس رتبهٔ افراد پایین جدول را نمی‌بیند.** تحقیر عمومی، ضد هدف است.
۴. **انصراف آزاد:** `profiles.show_in_leaderboard = false` کاربر را از جدول
   عمومی حذف می‌کند بدون اینکه امتیازش را متأثر کند.
۵. **جدول «بیشترین رشد»** در کنار جدول اصلی: کسانی که بیشترین افزایش امتیاز را
   در ۳۰ روز اخیر داشته‌اند. این به دانشجوی متوسطِ کوشا هم شانس دیده‌شدن می‌دهد.

```sql
-- بیشترین رشد ۳۰ روزه
SELECT user_id, SUM(amount) AS growth
FROM point_entries
WHERE created_at >= now() - interval '30 days'
  AND term_id = :current_term
GROUP BY user_id
ORDER BY growth DESC
LIMIT 10;
```

## ۹.۸ ضدبازی (Anti-Gaming)

| حملهٔ احتمالی | دفاع |
|----------------|------|
| ثبت انبوه ایدهٔ بی‌کیفیت | سقف ۳ در روز + امتیاز اصلی از رأی دیگران می‌آید |
| رأی متقابل دوستانه | یک رأی به‌ازای هر کاربر؛ الگوی رأی متقابل در گزارش مدیر علامت می‌خورد |
| ثبت شاخص فروش جعلی | امتیاز `METRIC_*` فقط پس از `verified_by` ثبت می‌شود |
| تلاش مکرر در آزمون | `QUIZ_SCORE` فقط برای **بهترین** تلاش، یک‌بار محاسبه می‌شود |
| باز و بسته کردن منابع | `RESOURCE_COMPLETED` یک‌بار به‌ازای هر منبع، کلید یکتا در دفتر کل |
| تشکیل تیم صوری | `TEAM_FORMED` فقط پس از اولین تحویل‌دادنی تأییدشدهٔ تیم |
| پروژهٔ شخصی خودتأییدی | پروژهٔ نوع `D` امتیاز `PROJECT_COMPLETED` **نصف** می‌گیرد و نیازمند تأیید منتور است |
| تکرار رویداد | کلید یکتای `(user, rule, source_type, source_id)` در دفتر کل |

**پایش:** گزارش هفتگی به مدیر شامل:
- کاربرانی با رشد امتیاز > ۳ برابر انحراف معیار
- نسبت امتیاز از فعالیت‌های خوداظهار به تأییدشده
- ایده‌هایی با الگوی رأی مشکوک

## ۹.۹ پیاده‌سازی

### سرویس امتیاز

```python
# apps/api/src/silp/domain/gamification/service.py

async def award(
    session: AsyncSession,
    *,
    user_id: UUID,
    rule_code: str,
    source_type: str,
    source_id: UUID | None,
    multiplier: Decimal = Decimal("1"),
    note: str | None = None,
    term_id: UUID | None = None,
) -> PointEntry | None:
    """ثبت امتیاز. در صورت تکرار، None برمی‌گرداند (بی‌اثر در تکرار)."""
    rule = await rules.get_active(session, rule_code)
    if rule is None:
        return None

    amount = (rule.base_points * multiplier).quantize(Decimal("0.01"))
    amount = await _apply_caps(session, user_id, rule, amount)
    if amount <= 0:
        return None

    entry = PointEntry(
        user_id=user_id, category=rule.category, rule_code=rule_code,
        amount=amount, source_type=source_type, source_id=source_id,
        term_id=term_id or await terms.current_id(session), note=note,
    )
    session.add(entry)
    try:
        await session.flush()
    except UniqueViolationError:      # کلید بی‌اثری
        await session.rollback()
        return None

    await events.publish(PointsAwarded(user_id=user_id, entry=entry))
    return entry


async def reverse(session, entry_id: UUID, reason: str) -> PointEntry:
    """اصلاح امتیاز با رکورد معکوس — هرگز حذف یا ویرایش (D-09)."""
    original = await session.get(PointEntry, entry_id)
    reversal = PointEntry(
        user_id=original.user_id, category=original.category,
        rule_code=original.rule_code, amount=-original.amount,
        source_type=original.source_type, source_id=original.source_id,
        reverses_id=entry_id, note=reason,
    )
    session.add(reversal)
    return reversal
```

### بازمحاسبهٔ گذشته‌نگر

وقتی مدیر قاعده‌ای را تغییر می‌دهد و بازمحاسبه می‌خواهد:

```
۱. همهٔ رکوردهای آن قاعده در بازهٔ انتخابی را بخوان
۲. برای هرکدام، رکورد معکوس بساز
۳. با قاعدهٔ جدید دوباره محاسبه و ثبت کن
۴. همه در یک تراکنش، با ثبت در audit_logs
۵. نمای تجمیعی را تازه‌سازی کن
۶. به کاربران متأثر اعلان بده: «امتیاز شما بازنگری شد»
```

**این عملیات هرگز رکوردی را پاک نمی‌کند.** تاریخچه کامل باقی می‌ماند.

## ۹.۱۰ تجربهٔ کاربری امتیاز

| اصل | پیاده‌سازی |
|-----|-----------|
| **شفافیت** | هر عدد در رابط، قابل کلیک و منتهی به `/me/points` با فیلتر همان منبع |
| **فوریت** | Toast با انیمیشن «+۵۰ امتیاز · تأیید مرحله» بلافاصله پس از عمل |
| **پیشرفت** | نوار سطح همیشه در هدر، با «۱۳۰ امتیاز تا سطح بعد» |
| **جشن** | نشان جدید ⇒ مودال تمام‌صفحه با انیمیشن، قابل اشتراک‌گذاری |
| **بدون تحقیر** | هرگز نمایش «تو از ۸۰٪ کلاس عقب‌تری». فقط رشد خودی. |
| **احترام به کاهش** | امتیاز منفی هرگز به‌صورت انیمیشن یا اعلان پرسروصدا نمایش داده نمی‌شود |

**قاعدهٔ حرکت (§10):** انیمیشن جشن ≤ ۱.۲ ثانیه و قابل رد کردن. جشنی که مزاحم شود،
دفعهٔ دوم آزاردهنده است.
