## دربارهٔ این سند

این سند، مرجع یکتای حقیقت (Single Source of Truth) برای پیاده‌سازی SILP است.
هر خطی از کد که نوشته می‌شود باید قابل ردیابی به بخشی از این سند باشد. اگر تناقضی
بین کد و این سند دیده شد، **سند اصلاح می‌شود، نه اینکه نادیده گرفته شود.**

سند v1 (فایل `CLAUDE.md` در ریشهٔ مخزن) بیانیهٔ چشم‌انداز است. این سند، ترجمهٔ آن
چشم‌انداز به مشخصات فنی اجراپذیر است.

## خلاصهٔ اجرایی

SILP یک پلتفرم یکپارچه است که چهار مسیر رشد دانشجو را در یک محیط واحد به‌هم می‌دوزد:

```
        ┌──────────────────────────────────────────────┐
        │              پروفایل یکتای دانشجو             │
        │   مهارت‌ها · امکانات · علاقه‌ها · اهداف        │
        └──────────────────────┬───────────────────────┘
                               │
              ┌────────────────┴────────────────┐
              │      موتور توصیه‌گر (§08)        │
              └────────────────┬────────────────┘
                               │
     ┌─────────┬───────────────┼───────────────┬──────────┐
     ▼         ▼               ▼               ▼          ▼
 ┌───────┐ ┌─────────┐   ┌──────────┐   ┌──────────┐ ┌─────────┐
 │ آموزش │ │  پژوهش  │   │ کارآفرینی │   │ حل مسئله │ │  تیم    │
 │  دروس │ │ Research│   │  Venture │   │Smart City│ │Formation│
 │ آزمون │ │   Hub   │   │ Incubator│   │   Lab    │ │         │
 └───┬───┘ └────┬────┘   └────┬─────┘   └────┬─────┘ └────┬────┘
     └──────────┴─────────────┴──────────────┴────────────┘
                               │
                    ┌──────────┴───────────┐
                    │  دفتر کل امتیاز (§09) │
                    │  رویدادمحور، تغییرناپذیر│
                    └──────────┬───────────┘
                               │
                    ┌──────────┴───────────┐
                    │   داشبورد و کارنامه   │
                    └──────────────────────┘
```

**تفاوت بنیادی با یک LMS معمولی:** در LMS، واحد ارزش «درس» است. در SILP، واحد ارزش
**«پروژه»** است و درس صرفاً مسیری برای آماده‌سازی دانشجو جهت ورود به پروژه است.
هر تصمیم طراحی باید این اولویت را بازتاب دهد.

## اصول طراحی محصول

**۱. پیش‌فرض‌های هوشمند به جای فرم‌های طولانی.**
فرم نیمرخ دانشجو (§۵ سند v1) طولانی است؛ آن را به چهار گام کوتاه با نوار پیشرفت و
امکان «بعداً تکمیل می‌کنم» می‌شکنیم. هر گام تکمیل‌شده بلافاصله ارزش برمی‌گرداند
(نمایش پیشنهادهای اولیه).

**۲. هر صفحه یک «قدم بعدی» روشن دارد.**
داشبورد خالی ممنوع است. هر حالت خالی (Empty State) باید یک دعوت به اقدام مشخص باشد.

**۳. شفافیت امتیاز.**
دانشجو باید بتواند روی هر عدد کلیک کند و ببیند از کجا آمده است. «جعبهٔ سیاه» اعتماد را می‌کشد.

**۴. آفلاین‌دوستی.**
اینترنت قطع می‌شود. جزوه‌ها قابل دانلود، فرم‌ها با ذخیرهٔ خودکار پیش‌نویس، و
آزمون با تحمل قطعی موقت (§07).

**۵. سبکی.**
بودجهٔ JavaScript صفحهٔ اول ≤ ۱۸۰KB فشرده. هر کتابخانهٔ جدید باید توجیه مکتوب داشته باشد.

**۶. کار با داده‌های واقعی از روز اول.**
داده‌های نمونه (§14) از دروس و پروژه‌های واقعی گرفته شده‌اند، نه Lorem Ipsum.

## واژگان یکدست (Ubiquitous Language)

این واژه‌ها در کد، دیتابیس و رابط کاربری **دقیقاً** با همین معنا به کار می‌روند.

| فارسی | English (کد) | تعریف |
|-------|--------------|-------|
| کاربر | `User` | هر حساب ثبت‌شده در سامانه |
| نیمرخ | `Profile` | اطلاعات دانشگاهی و شخصی کاربر |
| ارزیابی نیمرخ | `ProfileSurvey` | پاسخ‌های فرم مهارت / امکانات / علاقه |
| درس | `Course` | یک واحد درسی قابل ارائه (مثلاً «مهندسی ترابری») |
| ارائه | `CourseOffering` | ارائهٔ یک درس در یک نیم‌سال مشخص |
| ثبت‌نام | `Enrollment` | عضویت دانشجو در یک ارائه |
| هفته | `CourseWeek` | واحد محتوایی یک ارائه (۱ تا ۱۷) |
| آزمون | `Quiz` | مجموعه سوال زمان‌دار متصل به یک هفته |
| تلاش | `QuizAttempt` | یک بار شرکت دانشجو در آزمون |
| پروژه | `Project` | واحد اصلی خلق ارزش (نوع A/B/C/D) |
| درخواست پیوستن | `ProjectApplication` | تقاضای دانشجو برای پیوستن به پروژه |
| تیم | `Team` | گروه اجراکنندهٔ یک پروژه |
| مرحله | `Milestone` | نقطهٔ تحویل قابل ارزیابی در پروژه |
| تحویل‌دادنی | `Deliverable` | خروجی ارسالی دانشجو برای یک مرحله |
| ایده | `Idea` | ثبت اولیهٔ یک فکر در بانک ایده |
| کسب‌وکار | `Venture` | ایدهٔ ارتقایافته به استارتاپ با تیم و مدل درآمد |
| امتیاز | `PointEntry` | یک رکورد تغییرناپذیر در دفتر کل امتیاز |
| نشان | `Badge` | دستاورد قابل نمایش |
| نیم‌سال | `Term` | بازهٔ زمانی تحصیلی (مثلاً ۱۴۰۴-۲) |

> **قاعده:** هرگز از `Group` به‌جای `Team`، یا `Assignment` به‌جای `Deliverable`
> استفاده نکنید. یکدستی واژگان، هزینهٔ نگهداری را نصف می‌کند.
