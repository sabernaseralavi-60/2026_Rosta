# ۱۰ — سیستم طراحی

**هویت بصری SILP: «کارگاه، نه کلاس درس.»**

این سامانه جایی است که چیزی ساخته می‌شود. طراحی باید حس یک میز کار مرتب و
پرنور را بدهد — نه یک سالن امتحان سرد، و نه یک اپلیکیشن بازی پرزرق‌وبرق.

---

## ۱۰.۱ اصول طراحی

| اصل | معنای عملی |
|-----|-------------|
| **محتوا قهرمان است** | تزئین هرگز نباید جلوی خواندن را بگیرد. حداکثر یک عنصر تزئینی در هر صفحه. |
| **آرامش با لهجه** | پالت عمدتاً خنثای گرم، رنگ اشباع فقط برای اقدام و وضعیت. |
| **سلسله‌مراتب با فضا، نه خط** | جداکننده کم، فضای سفید زیاد. خط فقط وقتی فضا کافی نیست. |
| **حرکت هدفمند** | انیمیشن فقط برای توضیح تغییر حالت. بدون حرکت تزئینی. |
| **فارسی درجه‌یک** | تایپوگرافی فارسی باید بهتر از نسخهٔ انگلیسی باشد، نه ترجمهٔ ناشیانه. |
| **صداقت بصری** | حالت بارگذاری شبیه محتوای نهایی. بدون توهم سرعت. |

### آنچه عمداً نمی‌کنیم

- گرادیان بنفش-آبی (کلیشهٔ محصولات هوش مصنوعی)
- کارت‌های شیشه‌ای (glassmorphism) — در فارسی خوانایی را می‌کشد
- سایه‌های عمیق و پراکنده
- آیکن‌های سه‌بعدی و تصویرسازی‌های شلوغ
- انیمیشن ورود برای هر عنصر صفحه
- بیش از دو وزن فونت در یک صفحه

### قواعد استفاده از رنگ

| قاعده | جزئیات |
|-------|--------|
| **کنتراست** | متن اصلی ≥ ۷:۱، متن ثانویه ≥ ۴.۵:۱، عناصر تعاملی ≥ ۳:۱ |
| **رنگ تنها کافی نیست** | هر وضعیتی که با رنگ نشان داده می‌شود، آیکن یا متن هم دارد |
| **صرفه‌جویی** | در هر صفحه حداکثر یک عنصر با رنگ اشباع برند |
| **زعفرانی کمیاب** | فقط برای اقدام اصلی، نشان جدید، و دستهٔ کارآفرینی |
| **پس‌زمینه گرم** | هرگز سفید خالص برای بوم؛ `--neutral-50` چشم را کمتر خسته می‌کند |
| **متن رنگی فقط از نقش** | `text-[var(--fg-*)]`، هرگز پلهٔ پالت (`--brand-700`، `--danger-600`…) — M7-14 |

### نقش‌های متن (M7-14، ADR-0018)

ممیزی کامل نشان داد یک پلهٔ پالت برای متن در هر دو تم درست نیست
(`--brand-700` در تیره ۲٫۷ به ۱، `--warning-600` در روشن ۳٫۲ به ۱). متن رنگی
از این نقش‌ها می‌آید؛ همه روی سطح، بوم و پس‌زمینهٔ کم‌رنگ همان لحن ≥ ۴٫۵ به ۱‌اند:

| نقش | روشن | تیره |
|-----|------|------|
| `--fg-tertiary` | `oklch(53% 0.012 80)` | `oklch(65% 0.012 82)` |
| `--fg-brand` | `--brand-700` | `oklch(78% 0.1 183)` |
| `--fg-accent` | `--accent-700` | `oklch(76% 0.14 60)` |
| `--fg-danger` | `--danger-600` | `oklch(72% 0.15 25)` |
| `--fg-success` | `oklch(48% 0.125 150)` | `oklch(74% 0.14 150)` |
| `--fg-warning` | `oklch(50% 0.12 72)` | `oklch(80% 0.14 80)` |
| `--fg-info` | `oklch(50% 0.13 245)` | `oklch(74% 0.11 245)` |
| `--fg-research` | `oklch(50% 0.15 295)` | `oklch(74% 0.12 295)` |

در تیره: پله‌های `-50`/`-100` (پس‌زمینهٔ کم‌رنگ) تیره می‌شوند، `--fg-on-brand`
متن تیره است (سفید روی برند روشن‌شده ۲٫۵ به ۱ بود) و `--brand-700` (hover) یک
پله تیره‌تر از برند. `prefers-contrast: more` برای هر تم جدا تعریف شده است.
مقدار `--fg-tertiary: var(--neutral-500)` در بلوک بالا جایگزین شده است.

## ۱۰.۳ تایپوگرافی

### قلم

| نقش | قلم | دلیل |
|-----|-----|------|
| فارسی | **Vazirmatn** | متن‌باز، وزن‌های کامل، ارقام فارسی و لاتین، بهینه برای صفحه |
| لاتین و کد | **JetBrains Mono** | برای کد، شناسه، و اعداد جدولی |
| اعداد نمایشی | Vazirmatn با `font-variant-numeric: tabular-nums` | جلوگیری از پرش ستون اعداد |

```css
@font-face {
  font-family: 'Vazirmatn';
  src: url('/fonts/Vazirmatn[wght].woff2') format('woff2-variations');
  font-weight: 100 900;
  font-display: swap;
  unicode-range: U+0600-06FF, U+200C-200F, U+FB50-FDFF, U+0020-007F;
}
```

**قلم متغیر (Variable Font)** یک فایل ~۸۰KB به‌جای ۶ فایل جداگانه. الزامی است.

### مقیاس

مقیاس بر پایهٔ نسبت ۱.۲۵ (سوم بزرگ) با تعدیل برای فارسی. **فارسی به `line-height`
بیشتری از لاتین نیاز دارد** چون نویسه‌ها زیرنویس و بالانویس دارند.

| توکن | اندازه | ارتفاع خط | وزن | کاربرد |
|------|--------|-----------|-----|--------|
| `display` | ۳۶px | ۱.۳ | ۷۰۰ | عنوان صفحهٔ اصلی |
| `h1` | ۲۸px | ۱.۴ | ۷۰۰ | عنوان صفحه |
| `h2` | ۲۲px | ۱.۴۵ | ۶۰۰ | عنوان بخش |
| `h3` | ۱۸px | ۱.۵ | ۶۰۰ | عنوان کارت |
| `body-lg` | ۱۷px | ۱.۸ | ۴۰۰ | متن اصلی محتوای آموزشی |
| `body` | ۱۵px | ۱.۷۵ | ۴۰۰ | متن پیش‌فرض |
| `body-sm` | ۱۳.۵px | ۱.۷ | ۴۰۰ | متن کمکی |
| `caption` | ۱۲.۵px | ۱.۶ | ۵۰۰ | برچسب، فراداده |
| `mono` | ۱۳px | ۱.۶ | ۴۰۰ | کد، شناسه |

**قواعد تایپوگرافی فارسی:**

۱. `line-height` هرگز زیر ۱.۶ برای متن فارسی.
۲. طول خط ۶۵ تا ۷۵ نویسه (`max-width: 68ch`).
۳. `text-align: start` نه `right` — تا در حالت LTR هم درست کار کند.
۴. **نیم‌فاصله (U+200C)** در محتوا حفظ می‌شود؛ فقط در جستجو نرمال می‌گردد.
۵. اعداد در متن فارسی: **فارسی**. اعداد در جدول، کد و شناسه: **لاتین**.
   ```css
   .fa-digits { font-feature-settings: "ss02"; }   /* ارقام فارسی در Vazirmatn */
   .tabular   { font-variant-numeric: tabular-nums lining-nums; }
   ```
۶. وزن ۳۰۰ و کمتر برای متن بدنه ممنوع — در فارسی ناخواناست.
۷. `letter-spacing` برای فارسی **همیشه صفر**. فاصله‌گذاری حروف، اتصال را می‌شکند.

## ۱۰.۵ RTL — قواعد سخت‌گیرانه

**قاعدهٔ طلایی: هرگز از `left` و `right` استفاده نکنید.**

| ممنوع | به‌جای آن |
|-------|-----------|
| `margin-left` | `margin-inline-start` |
| `padding-right` | `padding-inline-end` |
| `text-align: right` | `text-align: start` |
| `border-left` | `border-inline-start` |
| `left: 0` | `inset-inline-start: 0` |
| `transform: translateX(10px)` | `translate: logical` یا متغیر جهت |
| `ml-4` (Tailwind) | `ms-4` |
| `pr-2` | `pe-2` |

در Tailwind v4 این‌ها بومی پشتیبانی می‌شوند. یک قاعدهٔ ESLint سفارشی، استفاده از
کلاس‌های فیزیکی را **خطا** اعلام می‌کند.

### موارد استثنا (باید فیزیکی بمانند)

| مورد | دلیل |
|------|------|
| نمودارها | محور زمان در نمودار همیشه چپ‌به‌راست است، حتی در فارسی |
| کد و ترمینال | `direction: ltr` اجباری |
| شمارهٔ تلفن، ایمیل، URL | `direction: ltr; unicode-bidi: isolate` |
| پخش‌کنندهٔ ویدئو | نوار پیشرفت چپ‌به‌راست |
| آیکن‌های جهت‌دار | باید آینه شوند: `←` `→` `↩` — با `[dir=rtl] & { scale: -1 1 }` |
| آیکن‌های غیرجهت‌دار | نباید آینه شوند: ساعت، جستجو، تنظیمات |

### دام رایج: اعداد و متن مخلوط

```html
<!-- غلط: ترتیب نمایش به‌هم می‌ریزد -->
<p>شمارهٔ شما 09121234567 است</p>

<!-- درست -->
<p>شمارهٔ شما <bdi dir="ltr">09121234567</bdi> است</p>
```

عنصر `<bdi>` برای هر متن با جهت نامشخص (نام کاربری، شماره، URL) الزامی است.

| معیار | هدف | سقف |

**راهبردها:**
- RSC برای همهٔ صفحات محتوایی؛ `'use client'` فقط برای تعامل واقعی.
- `next/font` با `display: swap` و زیرمجموعه‌سازی (subsetting) فارسی.
- تصاویر با `next/image` و AVIF/WebP.
- نمودارها با import پویا — کتابخانهٔ نمودار در بستهٔ اصلی نباشد.
- **بررسی خودکار بودجه در CI:** `scripts/check-bundle-budget.mjs` + شکست Build در صورت عبور.
- دیالوگ‌ها و هر چیزی که فقط با کنش کاربر باز می‌شود (پالت ⌘K، جشن سطح) با
  import پویا، نه در JS اولیهٔ پوسته.
- اسکلت بارگذاری هم‌قد بخش واقعی؛ جای محتوای مخصوص کاربر واردشده با
  `.signed-in-only` برای مهمان ساخته نمی‌شود؛ فیلتری که فهرست را عوض می‌کند،
  همان لحظهٔ کلیک اسکلت نشان می‌دهد.

**تعریف سنجش (M7-15):** «JS اولیه» = چانک‌های مشترک (`rootMainFiles`) + چانک‌های
صفحه + چانک‌های همهٔ layoutهای بالای آن، gzip، روی **سنگین‌ترین مسیر**. عدد
«First Load JS» خود Next چانک‌های layout را نمی‌شمرد. ۱۰۳KB از این عدد
زمان‌اجرای React و Next است؛ دروازه سقف است و عبور از هدف هشدار.
LCP، CLS و INP روی ساخت تولید با دو نمایه سنجیده می‌شوند: «4G کند» Lighthouse
(۱٫۶Mbps، ۱۵۰ms، CPU ×۴) و «4G معمول» (۹Mbps، ۶۰ms، CPU ×۲). نتیجهٔ M7-15 در
ADR-0018.
